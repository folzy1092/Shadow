# Shadow — личные наборы ESign

Утилита: `build-system/ci/prepare_esign_ipa.py`. Это один самостоятельный файл,
Python 3.9+; для окна нужен tkinter, обычно включённый в установщик python.org.
Сертификат, пароль, доступ к GitHub и сеть для неё не нужны.

## Окно

Откройте Python-файл или запустите без аргументов:

```sh
python3 build-system/ci/prepare_esign_ipa.py
```

1. Выберите готовый набор «Folzy» или введите новое название, например «Друг».
2. Введите Bundle ID, Team ID и APNs environment. Кнопка заполнения из
   `.mobileprovision` читает эти поля из entitlements профиля — это не проверка
   его CMS-подписи, срока/отзыва или разрешённого устройства.
3. Сохраните набор. При следующем открытии он останется в списке.
4. Выберите исходный IPA и нажмите «Подготовить отдельный IPA».
5. Укажите новое имя файла. Исходные и существующие готовые IPA не перезаписываются.
6. Подпишите полученную копию в ESign сертификатом и профилем выбранной Team.

Наборы хранятся локально: Windows — `%APPDATA%/ShadowESign/profiles.json`,
macOS — `~/Library/Application Support/ShadowESign/profiles.json`,
Linux — `$XDG_CONFIG_HOME/ShadowESign/profiles.json` или `~/.config/ShadowESign/profiles.json`.
Сохраняются только название, Bundle ID, Team ID и окружение. P12, пароли,
UDID и пути выбранных IPA не сохраняются. Файл наборов можно скопировать на
другой компьютер в соответствующее место. Кнопка удаления убирает только набор.

## CLI

```sh
python3 build-system/ci/prepare_esign_ipa.py \
  --input Telegram.ipa \
  --output Shadow-Folzy-ESign.ipa \
  --config build-system/shadow-esign.json
```

Конфигурация Folzy: Bundle ID `app.eclipse296.lake3160`, Team `336W4P3WL5`,
APNs `production`. Эти значения соответствуют представленному профилю;
идентификатор друга должен соответствовать его профилю, а не его Telegram ID.

## Что меняется

Меняется основной Info.plist: Bundle ID и соответствующие идентификаторы
фоновых задач. Исполняемые файлы, ресурсы, права ZIP и исходный IPA сохраняются.
Выходной файл создаётся после успешной подготовки в той же файловой системе;
для атомарной публикации нужна поддержка hard links (например, APFS/NTFS/ext4).

Скрипт **не подписывает приложение, не меняет entitlements в подписи, не
перевыпускает профиль и не создаёт APNs provider credentials**. Team/environment
записываются только как диагностические ожидания в Info.plist. Пока ESign не
переподпишет main executable и frameworks и не установит подходящий профиль,
эта копия не является готовой установочной сборкой.

Архивы с `.appex`/Watch отклоняются: для них нужен отдельный план профилей и
общей App Group. Произвольная группа из профиля не выбирается автоматически.
Смена Bundle ID означает отдельную установку и обычно повторный вход;
не удаляйте старый Shadow до сохранения его локального архива.

После ESign проверьте «Shadow → Диагностика push»: Bundle ID, подписанный
application-identifier и APNs environment должны соответствовать профилю.
Для реальных push серверу всё ещё нужны credentials соответствующего topic.

Подготовка личного IPA выполняется этой локальной утилитой после получения
сборки. Для работы окна не нужны GitHub workflow или дополнительный JSON-файл.
