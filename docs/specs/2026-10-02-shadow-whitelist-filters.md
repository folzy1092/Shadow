# Shadow: вайтлист устройств, патч-ноуты по сборкам, кнопка обновления, фильтры, скриншот сообщений

База: `master` @ `d6e00341bf`. Дата: 2026-10-02.

## 1. Вайтлист устройств

### Что видит пользователь
- Устройство не в списке: вместо приложения (до экрана входа и вместо списка
  чатов, если уже залогинен) — полноэкранная заглушка:
  «Доступ ограничен», ID устройства крупно, кнопки «Скопировать ID» и
  «Проверить снова». Ничего другого не открывается.
- Устройство в списке: приложение работает как обычно.

### ID устройства
- Генерируется при первом запуске (`UUID`, вид `XXXX-XXXX-XXXX-XXXX` для
  удобства пересылки) и хранится в Keychain (`kSecAttrAccessibleAfterFirstUnlock`,
  без iCloud-синхронизации).
- Переживает удаление/переустановку IPA, пока подпись (Team ID) та же.
  Сменился сертификат — ID новый, нужно добавить заново.
- UDID (`00008130-…`) приложение прочитать не может — в списке он не используется.

### Хранилище списка
- Файл `shadow-whitelist.json` в корне `master`, читается с
  `raw.githubusercontent.com` (как `shadow-update.json`, кэш GitHub до ~5 мин).
- Формат:
  ```json
  {
    "enabled": true,
    "devices": [
      { "id": "AB12-CD34-EF56-7890", "note": "мой 15 Pro" }
    ]
  }
  ```
  `enabled: false` — проверка выключена, пускать всех (аварийный рубильник).
  `note` только для людей, приложение его показывает в админ-меню.
- Сравнение ID без учёта регистра и пробелов.

### Когда проверяется
- При запуске и при возврате из фона (не чаще раза в 10 минут).
- Результат кэшируется на диске (последний успешный ответ).
- Нет сети / GitHub не ответил: решение по кэшу. Кэша нет (первый запуск) —
  заглушка с «Нет связи, проверка доступа» и «Проверить снова».
- Ответ пришёл, устройства в списке нет — заглушка сразу, даже если раньше пускало.

### Страховка от самоблокировки
- Если в приложении залогинен админ-аккаунт (Telegram ID `7878830498` — взят
  из `my_badge` в tgfork/config.json, **подтвердить**), проверка пропускается.
  Так ты не заблокируешь себя, если забыл добавить новый ID после переподписи.
  Работает, только если сессия уже есть (до входа проверка обычная).

### Где в коде
- Ядро: `TelegramCore/Sources/AyuGram/ShadowDeviceAccess.swift` — ID в Keychain,
  загрузка/парсинг/кэш, `status` (allowed / denied / unknown).
- UI заглушки: `TelegramUI/Sources/ShadowDeviceAccessUI.swift`; ставится в
  `ApplicationContext`/`AppDelegate` поверх root-контроллера (до авторизации и после).
- Тесты: парсинг и сравнение в `Tests/ShadowSettings` (Foundation-only + контракт).

### Ограничение (честно)
Проверка клиентская: кто умеет патчить IPA, её обойдёт. Это защита от
пересылки IPA «другу друга», не от реверса.

## 2. Админ-меню (только для тебя)

- Видно, если активный аккаунт = админ-ID. Последний пункт хаба Shadow:
  «Доступ устройств».
- Содержимое:
  - ID этого устройства + «Скопировать».
  - Текущий список из `shadow-whitelist.json` (ID + note), статус загрузки.
  - Поле «Вставить ID» + заметка → «Добавить»; свайп/кнопка «Удалить».
    Правки — локальный черновик.
  - «Скопировать JSON» — готовый файл целиком.
  - «Открыть на GitHub» — `github.com/folzy1092/Shadow/edit/master/shadow-whitelist.json`,
    вставляешь JSON, коммитишь. Токена в приложении нет.
- Коммит файла с `[skip ci]` в сообщении или только этот файл — CI можно не
  гонять (добавить `shadow-whitelist.json` в `paths-ignore` сборки).

## 3. Патч-ноуты только за пропущенные сборки

Текущая логика (`ShadowUpdateCheck.changes`) уже берёт записи
`installed < build <= announced`. Почему видна вся история — гипотезы:
1. `installedBuild == nil` (CFBundleVersion не число после переподписи) —
   тогда `?? 0` и показывается всё.
2. Пропущенные «версии» на деле несколько сборок (каждый пуш = сборка с записью).

Изменения:
- `installedBuild == nil` — показывать только запись объявленной сборки.
- В карточке писать «У тебя N → доступна M, пропущено K обновлений» —
  сразу видно, что приложение считает установленным.
- Каждая пропущенная сборка — отдельный блок; без общего обрезания до
  1500 символов (обрезать по блокам, если их больше 5: «и ещё N»).
- Тест на `changes(...)` с nil и с 1/3 пропущенными сборками.

**Нужно от тебя:** какая сборка стояла и какие номера были в карточке —
чтобы подтвердить гипотезу.

## 4. Кнопка обновления наверху хаба

- Первым элементом хаба — большая кнопка «Проверить обновления»
  (заливка акцентом, высота ~50, текст не меняется).
- Под кнопкой — строка статуса: «Проверяю…», «Актуально · сборка 34719»,
  «Доступна 34722», «Ошибка: …».
- Если доступно обновление — вторая большая кнопка «Скачать IPA (34722)»
  и под ней карточка с патч-ноутами (раздел 3).
- Старый пункт внизу хаба и баннер с markdown-ссылкой убрать.

## 5. Фильтры как в AyuGram Desktop

### Модель
```
ShadowMessageFilter {
  id: Int64
  expression: String      // регулярное выражение (NSRegularExpression)
  enabled: Bool
  caseInsensitive: Bool
  reversed: Bool          // «Обратный»: скрывать всё, что НЕ совпадает
  peerId: Int64?          // nil — везде, иначе только в этом чате
}
```
- Поле `messageFilters: [ShadowMessageFilter]` в `AyuGramSettings` (по чек-листу
  из `SHADOW_AGENT_MAP.md` §4: codable, transfer, document, поиск, тест).
- Миграция: старые `messageFilterPhrases` → фильтры с экранированным текстом,
  `caseInsensitive = true`. Старое поле читается, но больше не пишется.
- Невалидный regex не сохраняется (ошибка под полем ввода).
- Скомпилированные regex кэшируются (не компилировать на каждое сообщение).
- Как скрываем — как сейчас: свёрнутая плашка вместо сообщения/альбома.

### Экран «Фильтры»
- Список фильтров (выражение; подпись «везде» / имя чата; выключенные серые).
- Тап — редактирование, свайп — удалить. Сверху «Добавить фильтр».
- Окно «Добавить фильтр» как на скрине Desktop: поле «Выражение», галочки
  «Включить фильтр», «Без учёта регистра», «Обратный фильтр», плюс
  «Только в этом чате» (если открыто из чата). «Отмена» / «Сохранить».

### Точки входа
- Долгий тап по сообщению → контекстное меню (рядом с «Копировать»):
  «В фильтры» → окно с текстом сообщения (экранированным).
- Выделение текста в сообщении → в меню выделения рядом с «Копировать»:
  «В фильтры» → окно с выделенным фрагментом.
- В профиле чата/канала «…» → «Фильтры чата» (список только этого чата) —
  **опционально**, если не раздует объём.

## 6. Скриншот сообщений

### Пузыри ближе к аватаркам
Скрин с фото 780 px = 390 pt × 2 — это рендер «скриншота сообщений»
(`ChatControllerMessageScreenshot.swift`). Между аватаркой (x 8…40) и
пузырём ~16 pt. Сделать ~4–6 pt: колонка пузырей начинается с `40 + 4`,
у исходящих зеркально. Касается и входящих, и своих.

### Разрешение
- 116 px ширины — это даунскейл при загрузке в Claude: ПК-картинка пришла
  тоже 107 px. Само приложение такое не делает.
- Реальное ограничение есть: ширина рендера 390 pt, масштаб `≤ 2` и падает
  при длинной подборке (лимит 16 Мп и 16384 px по высоте). На 100 сообщениях
  ~1.6–1.9× → картинка ~620–740 px в ширину, на ПК шире.
- **Опционально:** рендерить с масштабом 3× (1170 px, как скрин iPhone) и
  при превышении лимита резать на несколько картинок вместо понижения
  масштаба. Делать?
